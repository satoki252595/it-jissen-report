### 3-1 AWS DataSync Enhanced modeがFSx for OpenZFSとNFS 4.2に対応

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	AWS DataSync の **Enhanced mode** が、Amazon FSx for OpenZFS を送受信先にできるようになった。オンプレ／FSx OpenZFS向けに **NFS 4.2** も選べ、オブジェクト転送ではユーザーメタデータをコピーするか制御する **ObjectMetadata** オプションが追加された。
</callout>

#### なぜ重要か
- これまで FSx for OpenZFS は Basic mode 限定で、Enhanced の性能・機能を使えなかった。
- NFS 4.2 のまま転送できるため、古いプロトコルへ落とす再設定が不要になる。

#### どう使うか
1. Enhanced mode の新規タスクで、場所に FSx for OpenZFS または NFS 4.2 を選ぶ。
2. Storage Gateway 配下のバケットなど、宛先メタデータを壊したくない場合は ObjectMetadata を調整する。
3. 既存タスクの挙動は変わらないため、移行は新規タスクから試す。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- ストレージ移行チームが、OpenZFS上の解析用データセットをクラウドへ移す作業を Enhanced mode に載せ替え、転送時間を短縮する。
</callout>

### 5-1 Ivanti Connect Secureに未認証RCE連鎖、限定的な悪用を確認

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Ivanti が Connect Secure の脆弱性を開示し、**限定的な悪用を認識**していると発表した。Volexityによると、認証バイパスとRCE（CVE-2026-104935）に権限昇格を連鎖させ、未認証でルート権限のコード実行に至る。当時最新だった 22.8R2.4 でも侵害例があり、パッチは2026-10-13に提供された。
</callout>

#### なぜ重要か
- VPN装置は社内への入口であり、完全パッチ済みでもゼロデイ連鎖の対象になった。
- 権限昇格側は別途修正予定とされ、パッチ適用後も監視が必要。

#### どう使うか
1. 影響版を使っていれば、公式アドバイザリの修正版へ即更新する。
2. Integrity Checker Tool を定期実行し、横移動の兆候がないかVPN起点のログを確認する。
3. 侵害兆候があれば、フォレンジック調査を前提に切り替える。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**

### 5-2 SAP Cloud SDK for PythonにCVSS 10.0のOAuth2 SSRF

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	SAP Cloud SDK for Python に、マルチテナントBTPアプリで `tenant_subdomain` を攻撃者が制御できると、OAuth2トークン要求を不正なサーバへ向けクライアント資格情報を漏らす **SSRF（CVE-2026-89111、CVSS 10.0）** がある。修正は **0.45.2**（RFC 1123ラベル検証）。GitHub Advisoryは2026-10-13公開。
</callout>

#### なぜ重要か
- テナント名の検証不足が、資格情報窃取に直結する。
- 修正は8月リリースに含まれていたが、公式アドバイザリ公開が10月になった点に注意。

#### どう使うか
1. `sap-cloud-sdk` の版を確認し、0.45.2以上へ上げる。
```bash
pip show sap-cloud-sdk
pip install 'sap-cloud-sdk>=0.45.2'
```
2. すぐ上げられない場合は、登録済みテナントの許可リストで `tenant_subdomain` を検証する。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- BTP上のマルチテナントSaaS開発チームが、依存SDKの緊急アップデートとテナント入力の許可リストを同日に入れる。
</callout>

- 以前はコンテキスト欠落でセキュリティルールやBot判定がずれ、誤った403が出ることがあった。
- 設定変更なしで自動適用される。

#### どう使うか
1. BYOIP＋Workers構成で、サブリクエスト時の誤検知／誤403が減ったかログで確認する。
2. セキュリティルールとBotスコアが、エンドユーザー起点で一貫しているかをレビューする。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- 自社IPで公開するAPIの前段にWorkersを置く構成で、内部サブリクエスト起因の誤ブロックを減らし、サポート問い合わせを減らす。
</callout>
