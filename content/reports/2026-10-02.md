## 🤖 AI / LLM / エージェント {color="purple"}

### 1-1 AWS、Strands Decider 2BをOSS公開

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	AWSがエージェント向けの小型意思決定モデル **Strands Decider 2B** をオープンソースで公開した。TypeSafeのJevに着想を得ており、事前に決めた選択肢から選び、**信頼度スコア**付きで返す。ベースはQwen3.5-2Bで、ローカル実行できるサイズ。
</callout>

#### なぜ重要か
- エージェントの各ステップで「次に何をするか」を毎回フロンティアLLMに聞く必要がなくなる
- 閉領域の選択肢＋信頼度により、ワークフローを低遅延・低コストで組み立てやすい
- Jevbenchで同サイズ帯の上位に入った後、Strands Labsとして正式公開された

#### どう使うか
1. エージェントの分岐点（次アクション選択、ルーティング）をDeciderに切り出す
2. 信頼度が低いときだけ大きいモデルへエスカレーションする方針を決める
3. OSSとして手元評価し、レイテンシと校正精度を実ワークフローで測る

```bash
# 公式案内に従いモデルを取得し、選択肢付きの意思決定タスクで評価する
# （配布チャネルはAWS Strands Labsの公開情報を確認）
```

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- カスタマーサポートBot: FAQ分岐をDeciderに任せ、曖昧なときだけGPT級モデルへ渡す
	- 社内自動化: 承認フローの次ステップ選択を低コスト化し、月次推論費を抑える
</callout>

### 1-2 Google Research、WikiSkillを公開

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Google ResearchとVirginia Techが **WikiSkill** を発表した。エージェントの実行トレースから構造化wikiを作り、失敗・成功の知見をスキル（`SKILL.md`）へ反映する。推論時のプロンプトにはコンパクトなスキルだけを載せ、wikiは進化フェーズで使う。
</callout>

#### なぜ重要か
- スキル進化系は診断結果を捨てがちで、同じ失敗を繰り返し再発見しやすい
- 実験では既存手法を平均で数〜十数ポイント上回り、モデル規模が大きいほど利得が伸びた例がある
- エンタープライズが既に持つ実行ログを「再利用可能なスキル資産」に変えられる設計

#### どう使うか
1. 本番エージェントの成功／失敗トレースを不変ログとして保存する
2. オフラインでwiki更新→スキル提案→検証セット合格時のみ採用、のループを回す
3. 推論プロンプトには短いスキルだけを入れ、wiki全文は載せない（コストと焦点の分離）

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- 社内コーディングエージェント: 過去の失敗パターンをwiki化し、同じ落とし穴への再突入を減らす
	- RPA／業務自動化: 手順書を手書きせず、実行履歴からスキルを育てる運用を試す
</callout>

### 2-2 Solid-Vue、ページレイアウトとOctans UIアドオン

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Solid-Vueが **ページ単位レイアウト**（Vue Routerの`definePage()`）と、初のUIキット連携 **Octans UI** アドオンを追加した。レイアウトは`src/layouts`の規約で選び、アドオンはプロバイダ登録まで自動化する。
</callout>

#### なぜ重要か
- 認証画面とダッシュボードでシェルが違う、という構造をルーティング設定ファイルなしで表現できる
- UIキット導入の定型作業をアドオン化し、プロジェクト立ち上げの摩擦を減らす
- 既存ファイルを安全に変更できない場合は自動編集せず、手動手順を返す設計

#### どう使うか
1. `src/layouts`に`default.vue`／`dashboard.vue`などを置く
2. 各ページで`definePage({ meta: { layout: 'dashboard' } })`を指定する
3. UIキットは `npx solid-vue add octans-ui` で配線する

```ts
definePage({
  meta: {
    layout: 'dashboard',
  },
})
```

```sh
npm create solid-vue@latest my-app
cd my-app
npx solid-vue add octans-ui
```

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- 小規模SaaS: 管理画面と公開ページのシェル分離を、初期から規約で固定する
	- 内製ツール: Octans UIアドオンで見た目の立ち上がりを早め、機能実装に時間を回す
</callout>

### 3-2 Cloudflare K2：サーバーレスイベントストリーム

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Cloudflareが **K2** をパブリックベータで公開した。R2上に順序付きログを持つサーバーレスのイベントストリームで、複数コンシューマへのファンアウトや長期保持が可能。Workers Paid向けで、ベータ期間は課金なし。
</callout>

#### なぜ重要か
- Queues（作業項目）やBasin Pipelines（オブジェクト／Iceberg向け取り込み）と役割が分かれ、高スループットのカスタム処理向け
- Kafka相当をエッジで動かす代わりに、オブジェクトストレージへセグメント書き込みする設計
- 初期はp99プロデュース遅延がおおよそ1秒と案内されている

#### どう使うか
1. `cf k2 streams create` でストリームを作成する
2. WorkerバインディングまたはHTTPでイベントを送信する
3. subscriptionを作り、`consume` → `ack`／`nack`／lease延長で処理する

```bash
cf k2 streams create --name app_events --http-enabled
```

```js
const result = await env.EVENTS.send([
  {
    content: new TextEncoder().encode(
      JSON.stringify({ event: "page_view", path: "/", timestamp: Date.now() }),
    ),
    headers: { "content-type": "application/json" },
  },
]);
```

ベータ上限の目安: ストレージ最大10GB、ストリームあたりプロデュース30 MB/s。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- プロダクト分析: ページビューをK2に貯め、分析ワーカーと不正検知ワーカーで並列消費する
	- イベント駆動SaaS: 下流障害中もイベントを保持し、復旧後に追いつき処理する
</callout>

### 3-3 Cloudflare Basinが一般提供開始

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Cloudflareが **Basin** を一般提供すると発表した。Apache IcebergとR2上で、取り込み・カタログ・クエリをサーバーレスに行うデータ基盤。クラウド間のデータ移動手数料なしを訴求している。

#### なぜ重要か
- 専用クラスタ前提の分析基盤を、エッジの従量モデルへ寄せられる

- Anomaly（OpenCode）などが既存のS3＋Athena構成からの移行事例として紹介されている

#### どう使うか
1. [Basinの開発者ドキュメント](https://developers.cloudflare.com/basin)から取り込みとCatalogを設定する
2. 既存イベントはBasin Pipelines経由、カスタム処理はK2、分析テーブルはBasin、と役割を分ける
3. 他クラウドのクエリエンジンからIcebergを直接読む構成を検証する

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- データチーム不在のプロダクト組織: イベント分析をサーバーレスで開始し、運用負荷を抑える
	- マルチクラウド分析: エグレス料金を気にせず、外部エンジンから同じIcebergを参照する
</callout>

### 4-1 Armadin、Series Bで$255.5M調達（評価額$25億超）

	**何が新しいか**
	Mandiant創業者Kevin Mandiaの **Armadin** が、Andreessen HorowitzとAccel主導のSeries Bで **$255.5M** を調達した。評価額は$25億超。3月のSeries A $190Mから約6か月で、累計調達は$445M超。

#### なぜ重要か
- 従来のスポット的ペンテストではなく、**常時稼働のエージェントswarm**で脆弱性を連鎖検証するモデル

- GV、In-Q-Tel、Kleiner Perkinsなど大手が並ぶ大型ラウンド

#### どう使うか
1. 自社のペンテスト頻度とスコープを見直し、常時検証が必要な資産を洗い出す
2. エージェントによる自動攻撃検証を導入する場合、本番影響と法務／契約条件を先に固める
3. 競合サービスとの差分（swarm連鎖 vs 単発スキャン）を評価観点に入れる

<callout icon="💼" color="green_bg">
	**ビジネス活用例**

	- セキュリティベンダー: 「エージェント対エージェント」の防御検証市場が本格化しているシグナルとして捉える
</callout>

### 4-2 a16z、doxxnetのSeries Aを主導

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Andreessen Horowitzが **doxxnet** のSeries Aを主導すると発表した。人とエージェント向けに、インターネットと並列のプライベートネットワーク（独自バックボーン・DNS・証明書基盤）を提供する。Agentic Defined Networkingと呼ぶ。
</callout>

#### なぜ重要か
- エージェントがアカウントやAPIに代理アクセスする世界では、通信経路のプライバシーが個人の問題になる
- VPNの置き換えではなく、P2P通信・非インターネットドメイン・DNSレベル脅威防御まで含む設計
- Prolexic創業者Barrett Lyonが主導し、ネットワーク防衛の実績を前面に出している

#### どう使うか
