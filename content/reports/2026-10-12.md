## 🤖 AI / LLM / エージェント {color="purple"}

### 1-1 Context Language Models：モデルが自分の文脈を編集する

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	Meta、MIT、ワシントン大学の研究者が、LLMが自分のコンテキストを「自由に書き換えられるファイル」として扱う手法 CLM を発表した。要約・圧縮・検索といった外部の仕組みに頼らず、古いメッセージの書き換えや進捗メモの維持をモデル自身が行う。
</callout>

#### なぜ重要か
- ゼロショットでも BrowseComp-Plus で**精度11.4%向上・FLOPs 21.5%削減**と報告されている。
- 強化学習では Qwen3.5-9B の BrowseComp-Plus が 28.8% から 42.5% に上がり、FLOPs は12%減った。
- 一方で、重要情報を捨てる危険や、編集可能な文脈がプロンプトインジェクションの持続経路になるリスクも指摘されている。

#### どう使うか
1. 自社エージェントの長時間タスクで、コンテキスト圧縮の方針を自然言語で指示する（CLM の in-context 方式の考え方）。
2. 「捨てた情報」「残した理由」をログに残し、後から検証できるようにする。
3. 文脈の書き換えはキャッシュを無効化するため、コストへの影響を計測してから採用する。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- 調査・リサーチ代行エージェントで、進捗メモと失敗した試行の記録を文脈に残す運用にし、長時間タスクの再試行コストを下げる。
</callout>

### 1-2 Odyssey-3：世界モデルの公開リサーチプレビュー

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	米 Odyssey が世界モデル Odyssey-3 の公開リサーチプレビューを始めた。テキストから対話可能な環境をリアルタイム生成し、一人称・三人称で移動やイベント発生ができる。モデル自体は9月15日に発表済みで、今回の新しさは**一般公開**と技術詳細・ベンチマークの公開。
</callout>

#### なぜ重要か
- 仮想世界の生成だけでなく、シミュレーション内のロボットアームやドローン、ゲームキャラクターの制御基盤を狙っている。
- 無料デモは Odyssey-3 Flash で動き、開発者は API アクセスを申請できる。
- WorldMark ベンチマークで複数の評価区分の首位を同社が主張している（自己申告値）。

#### どう使うか
1. 無料デモで、自社の用途（訓練シナリオ、ゲームのプロトタイプ）に近いプロンプトを試す。
2. 実用性があれば API アクセスを申請し、生成結果の物理的な一貫性を自社で評価する。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- ゲーム企画チームが、企画会議の前に遊べるプロトタイプ世界を数分で用意し、コンセプト検証を早める。
	- ロボット開発チームが、実機テスト前の操作シナリオ検討に使う。
</callout>

### 2-1 TanStack Query 5.104.2：Preact v11 対応と mutation の修正

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	TanStack Query のリリースで、preact-query が **Preact v11 に対応**した。query-core では、ウィンドウ非フォーカス時にもキュー済みのスコープ付き mutation が開始されるよう修正された。
</callout>

#### なぜ重要か
- mutation-observer が、コールバック実行前に mutateOptions のスナップショットを取るよう修正された。
- vue-query で `MutationResult` 型がエクスポートされた。
- リポジトリ内部では ESLint→oxlint、Prettier→oxfmt への置き換えと、TypeScript 7.1 プレビューのテスト追加が行われた。

#### どう使うか
1. 依存を更新し、mutation のコールバック周りのテストを流す。
```bash
npm i @tanstack/react-query@5.104.2 @tanstack/react-query-devtools@5.104.2
```
2. バックグラウンドタブで mutation を投げる画面（オフライン対応など）の挙動を確認する。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- フィールド業務アプリで、タブ切替中に送信した更新が保留されたままになる不具合の解消を確認し、データ欠落の問い合わせを減らす。
</callout>

### 3-1 Gremlin Foresight AI：障害テストを回すエージェントが一般提供

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	カオスエンジニアリングの Gremlin が、エージェント製品 Foresight AI を一般提供した。サービスの潜在障害を分析し、修正を提案し、**同じテストを再実行して修正を確かめる**閉ループを持つ。Gremlin プラットフォームのアドオンとして提供される。
</callout>

#### なぜ重要か
- Analyst、Tester、Operator、Technical Program Manager の4役割のエージェントで分業する。
- テストの実行も修正の適用も、人の承認なしには行わない設計になっている。
- 判断は10年以上の障害注入実験から作った「Failure Atlas」に基づき、顧客のシステムデータはLLM学習に使わないとしている。

#### どう使うか
1. 重要サービスを1つ選び、Analyst の推奨テストを承認制で実行する。
2. 失敗したテストに対する修正提案を確認し、再テストで合格するかを見る。
3. 週次レポートを Slack に流し、信頼性スコアの推移を共有する。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- AIで実装速度が上がったチームが、リリース前の耐障害性チェックを自動化し、「防いだ障害」を経営向けレポートで見える化する。
</callout>

### 3-2 EventBridge の強化版カスタムイベントバス（機能は9月発表）

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	InfoQ が10月11日に詳しく解説した。機能自体は**2026年9月24日に AWS が発表済み**で、新しい機能ではない。組織全体で1本のバスを共有でき、順序保証、イベントリプレイ、内容ベースの重複排除を備える。
</callout>

#### なぜ重要か
- 新しい Subscriber リソースが、フィルタ・変換・配信先・リトライ・DLQ を1つにまとめる。
- 料金はイベント数課金から、パブリッシャーがイングレス、サブスクライバーがイグレスを払う転送量課金に変わる。
- 東京を含む14リージョンで利用でき、従来のバスは「Classic」として併存する。

#### どう使うか
1. 新規のイベント基盤から強化版バスを使い、既存バスは移行ガイドに沿って段階的に移す。
2. チームごとに Subscriber を作り、費用をチーム別に配賦する。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- 複数アカウントで動くマイクロサービス群の、バス間ルーティング設定と二重課金を整理し、運用工数とコストを下げる。
</callout>

### 4-1 データセンター反対運動と NDA 廃止

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	TechCrunch の Equity が、Amazon が Microsoft に続いて自治体との交渉で NDA を使わないと表明した件を議論した。出演者は、NDA廃止は**信頼回復の第一歩**だが、それだけで反対派が納得するわけではないと見ている。
</callout>

#### なぜ重要か
- 電気料金、水使用量、地価への影響が説明されないことが不信の核心とされる。
- 各地のモラトリアムは1〜2年程度のものが多く、長期的な効果は不透明という見方も出た。

#### どう使うか
1. 自社がデータセンターや大型設備を誘致・利用する場合、地域への影響データを早めに公開する前提で計画する。
2. クラウド選定時に、事業者の地域対応や透明性の方針も評価項目に入れる。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- ESGレポートを作る企業が、利用クラウドのデータセンターの電力・水の開示状況を調達基準に加える。
</callout>

### 4-2 音声AIはまだ「ChatGPTモーメント」に達していない

<callout icon="📌" color="gray_bg">
	**何が新しいか**
	PolyAI の CTO と Otter の CMO が、全二重モデルが出ても音声AIはまだ転換点に達していないと語った。次の課題は**推論の高速化**と、音声認識（ASR）の精度だという。
</callout>

#### なぜ重要か
- ASR がキーワードを取りこぼすと、要約や後続の自動アクションがすべて誤る。
- AIとの通話や録音であることを相手に明示する透明性が、信頼の条件として挙がった。

#### どう使うか
1. 音声ボット導入時は、専門用語や固有名詞の認識精度を最初に検証する。
2. 通話の冒頭で「AIが対応している」ことを案内する設計にする。

<callout icon="💼" color="green_bg">
	**ビジネス活用例**
	- コールセンターが、自社の製品名・型番の辞書を整備したうえで音声AIを試し、一次対応の完結率を測る。
</callout>
