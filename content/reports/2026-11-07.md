### 1-1 AWS Agent RegistryがGovCloud（US-West）でGA

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

Amazon Bedrock AgentCore経由の<b>AWS Agent Registry</b>が、AWS GovCloud（US-West）で一般提供になった。MCPサーバー、ツール、エージェント、agent skills、カスタムリソースを中央カタログへ登録し、承認ワークフローで公開範囲を制御できる。
</callout>

#### なぜ重要か

- 人とAIエージェントの両方が、ハイブリッド検索・カタログ閲覧・ネイティブMCPエンドポイントから「使える道具」を探せる。
- 公共機関向けに、承認フローとCloudTrail監査ログでコンプライアンス要件を満たしやすい。
- エージェント乱立によるシャドーITを、レジストリ経由の発見に寄せられる。

#### どう使うか

1. GovCloud（US-West）でAgent Registryを有効化し、まず社内MCPサーバーと既存エージェントを登録する。
2. 承認ワークフローで「誰が何を公開できるか」を決め、CloudTrailで登録・変更を監視する。
3. エージェント側はレジストリのMCPエンドポイントを参照し、個別URLハードコードを減らす。

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

- 公共・金融のSI案件で、許可済みエージェント／ツールの棚卸し基盤としてAgent Registryを提案する。
- 社内AI基盤チームが、部門ごとのMCPサーバーを中央カタログに集め、重複開発を抑える。
</callout>

### 2-1 Vercel Tracingが一般提供

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

Vercel Tracingが全プランで一般提供になった。ダッシュボードとCLI（`vercel traces search`）からトレースを検索・検査でき、Next.js 16.5以降の新規プロジェクトは初回成功ビルド後にトレーシングが既定で有効になる。
</callout>

#### なぜ重要か

- ベータ時はログ画面からの個別オープン中心だったが、Tracesページでチーム横断のSpans／Traces一覧とKQL検索が使える。
- Hobbyは3日、Pro／Enterpriseは14日へ保持期間が延び、障害調査の窓が広がる。
- 価格はベータと同じ。サンプリングルールを全削除すればオプトアウトできる。

#### どう使うか

1. 既存プロジェクトでは Settings → Tracing でサンプリングルールを追加し、本番の遅いDB spanをKQLで探す。
2. CLIで同じクエリを再利用する（例: `vercel traces search --query 'span.duration > 2000'`）。
3. 新規Next.jsは初回ビルド後の自動ルールを確認し、不要ならルールを削除してオプトアウトする。

```bash
vercel traces search --query 'span.duration > 2000'
vercel traces search --status error --since 1h
```

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

- Next.js BFFの遅延を、ダッシュボードのKQLでDB spanに絞って週次レビューする。
- SREがCLIでエラーstatusのトレースを引き、インシデント初動の情報収集を揃える。
</callout>

### 2-2 Cloudflare、User APIトークン作成UIを刷新

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

CloudflareのUser APIトークン作成体験が、Account APIトークンと同系統のダッシュボードUIへ刷新された。ポリシーの追加・編集・削除、有効期限プリセット、クライアントIP制限を作成画面でまとめて確認できる。
</callout>

#### なぜ重要か

- トークン種別が違っても操作感が揃い、権限設計のレビュー漏れを減らせる。
- 動作自体は従来どおり「作成ユーザー代理」のまま。Accountトークンと混同しない注意は必要。
- CIや個人スクリプト用の短期トークンを、期限とIP制限つきで作りやすい。

#### どう使うか

1. ダッシュボードでUser APIトークンを新規作成し、最小権限のポリシーだけ残す。
2. 有効期限と許可IPを同じ画面で設定し、レビュー後に発行する。
3. 既存の長期トークンは棚卸しし、期限付きへ置き換える。

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

### 3-1 EC2 Capacity Blocks for MLの前払い費用を按分表示

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

AWS Data Exports（CUR 2.0）とCost Explorerが、Amazon EC2 Capacity Blocks for MLの前払い料金を予約期間へ按分表示するようになった。起動インスタンスごとの償却コストと、未使用分の償却コストを並べて見られる。
</callout>

#### なぜ重要か

- これまで前払いは購入日に一括計上され、どのジョブがGPU枠を使ったか配賦しにくかった。
- CURでは `reservation_amortized_upfront_fee_for_billing_period` や `reservation_effective_cost` などで確認できる。
- 追加料金なし。GovCloud（US）と中国リージョンは対象外。

#### どう使うか

1. Cost Explorerでamortized costビューを開き、Capacity Blockの配賦をチーム／プロジェクト単位で確認する。
2. CUR 2.0の該当列をデータマートへ取り込み、未使用枠の比率をダッシュボード化する。
3. 次回のCapacity Block購入サイズを、未使用率を見ながら見直す。

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

- ML基盤のFinOpsで、GPU前払いを研究チーム別に配賦し、空き枠の削減計画を作る。
</callout>

### 5-1 AWS Security HubがSBOMインベントリを提供

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

AWS Security Hubが、Amazon Inspectorが生成するSBOMをもとに、組織横断のソフトウェア部品表インベントリを提供し始めた。対象はEC2、ECRイメージ、Lambda。追加設定なしで、パッケージ名・版数・型・導入リソース数を一覧できる。
</callout>

#### なぜ重要か

- 中央セキュリティチームが「どの計算資源にどの版が入っているか」を横断検索できる。
- リソース詳細のInstalled softwareタブやSecurity Hub APIからも照会できる。
- Security Hub Essentialsに含まれ追加料金なし。Inspectorが有効な場所で自動投入される。

#### どう使うか

1. Inspectorが組織アカウントで有効か確認し、Security HubのSBOMページで危険パッケージを絞る。
2. 脆弱性トリアージ時にInstalled softwareタブで当該ホストの役割を判断する。
3. APIでインベントリを定期エクスポートし、社内CMDBや許可リストと突合する。

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

- セキュリティ運用で、緊急CVE発表後に「影響パッケージを持つLambda／EC2」をSBOM画面から即抽出する。
</callout>

### 5-2 Istio 1.30.8／ISTIO-SECURITY-2026-009

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

Istioがセキュリティ修正入りの<b>1.30.8</b>（および1.31系は1.31.4以降）を公開し、ISTIO-SECURITY-2026-009で複数件を開示した。最高はambientモードでのポート単位STRICT PeerAuthentication回避（GHSA-rr2c-p22p-6r9r、CVSS 8.2）。
</callout>

#### なぜ重要か

- ambientでメッシュ全体STRICTでも、ワークロードがPERMISSIVE／DISABLEだと平文が届くケースがある。
- サイドカーのconntrack再利用によるプロキシ回避、istiodクラッシュ（デバッグxDS）、マルチクラスタでのCLUSTER_ID詐称によるSDS秘匿情報取得なども含まれる。
- AuthorizationPolicyのHost条件の大小文字差や、ambient waypointのipBlocksが内部アドレスを見る問題もfail-openになり得る。

#### どう使うか

1. 1.30系は1.30.8以上、1.31系は1.31.4以上へ上げる。
2. ambient利用時はPeerAuthenticationと空のto／fromを持つAuthorizationPolicyを見直す。
3. Host条件は大小文字を意識したテストを追加し、IP拒否は必要なら`remoteIpBlocks`等へ切り替える。

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

- サービスメッシュ運用チームが、本番ambient／サイドカーの版数を当日確認し、セキュリティパッチを週次枠より前倒しする。
</callout>

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

#### なぜ重要か

#### どう使うか

2. メモリ逼迫するINサブクエリにスピル設定を試し、ピークメモリを測る。
3. 読みやすい関数合成へ段階的に書き換え、EXPLAINで従来ラムダと同値か確認する。

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

### 8-2 Glue Data CatalogがIceberg用catalog-vended認証に対応

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

AWS Glue Data CatalogのApache Iceberg RESTカタログ連携が、外部カタログが発行する一時クレデンシャル（catalog-vended credentials）を使えるようになった。Athena／EMR／Redshift／Glueから、外部カタログが許可したテーブルだけを読める。
</callout>

#### なぜ重要か

- 従来はS3へ届くIAMロールを自前で張る方式が中心だったが、外部カタログ側のテーブル権限に寄せられる。
- 一時クレデンシャルはS3プレフィックスにスコープされ、Lake Formationで行・列レベル制御やアカウント横断共有もできる。
- 商用リージョンでGlue／Lake Formationが使える場所が対象。

#### どう使うか

1. 外部Iceberg RESTカタログがvended credentialsに対応しているか確認する。
2. Lake Formation経由でフェデレーションを設定し、Athenaで許可テーブルのみ見えることを検証する。
3. 既存の広いS3 IAMロール連携から、必要テーブルだけの権限へ段階移行する。

- マルチクラウド／パートナー共有のIceberg資産を、最小権限の一時クレデンシャルで自社分析エンジンへ取り込む。
</callout>

### 9-1 Claude Enterpriseのプロジェクトタグ（原価コード）

<callout icon="📌" color="gray_bg">
<b>何が新しいか</b>

Claude Enterpriseで、プロジェクトに原価コード／WBS／クライアント案件番号などの<b>プロジェクトタグ</b>を付け、利用額の大半をタグ別に集計できるベータが始まった（リリースノート 2026-11-06）。Ownerがタグを定義し、プロジェクト編集者が値を設定する（最大16タグ／プロジェクト）。
</callout>

#### なぜ重要か

- 部門・案件単位のAI利用費を、既存の会計コード体系に寄せて見える化できる。
- プロジェクト外の利用は「Not in a project」になり、Claude Codeは`attributionProject`設定が必要。
- HIPAA／CMEK／ZDR構成や米国外データ保管では利用不可など、前提条件が明確。

#### どう使うか

1. Organization settings → Project tags で `cost_code` などを作り、必須化するか決める。
2. 主要プロジェクトへ値を付け、Usage → Spend by project で Group by する。
3. Claude Code利用端末は `.claude/settings.json` に `attributionProject` を入れ、漏れを減らす。

```json
{ "attributionProject": "PROJECT_ID" }
```

<callout icon="💼" color="green_bg">
<b>ビジネス活用例</b>

- AI推進室が案件別のClaude費用を月次で原価コードへ紐づけ、請求・予算消化の説明資料を作る。
</callout>
