# IT実践レポート

AIからネットワークまで、11の領域の動きを現場の判断に使える形で毎日公開する静的サイトです。

公開先: https://satoki252595.github.io/it-jissen-report/

## 新しい号を追加する

1. Notionから書き出したMarkdownを `content/reports/YYYY-MM-DD.md` として置く。
2. ファイル名の日付が、その号の日付になる。フロントマターは不要。
3. `main` へプッシュすると、GitHub Actionsがビルドして GitHub Pages に公開する。

対応しているNotion由来の記法は、`<callout>`、`<details>`、見出しの `{color="..."}` と `{domain="..."}`、`header-row` 付きのHTML表、コードブロックです。`<table_of_contents/>` はビルド時に除き、ページ側の目次を使います。

## 領域

領域は次の11個で、`src/config/domains.js` の配列の順に並びます。

1. 🤖 AI・LLM・エージェント
2. 🌐 Web・フルスタック
3. ☁️ クラウド・インフラ・DevOps
4. 📊 データ・スタートアップ・トレンド
5. 🛡️ セキュリティ
6. 🏛️ アーキテクチャ・設計
7. 🧩 言語・ランタイム・OSS
8. 🗄️ DB・データ基盤
9. 🛠️ 開発プロセス・チーム
10. 📱 モバイル・フロント端末
11. 📡 ネットワーク

号に含める領域は、このうちの一部だけでよい。見出しの下にトピックがない領域は、その号のページには出さない。ホームでは11領域をいつも表示し、その日のトピックがなければ「本日は該当なし」と直近のトピックを出す。同じトピックが複数の号にある場合、ホームでは最新の号だけを出す。既存の号は先頭の4領域だけで、本文中のセキュリティや設計の記述は移動しない。

領域を増やすときは、`src/config/domains.js` に1件足す。スラッグ、絵文字、短いラベル、表示名、タグの背景色と文字色を書く。`legacyColor` は既存の Notion 色（`purple` / `blue` / `orange` / `green`）用で、新しい領域では `null` にする。

号の `##` 見出しは、次のどれかで領域になる。

- 絵文字（`## 🛡️ セキュリティ`）
- `{domain="security"}`
- `{color="security"}`
- 従来の4領域だけ `{color="purple"}` のような Notion の色

タグの色は領域の背景にだけ使い、リンクとフォーカスのアクセント色とは分ける。

## デザインの原則

国際アワード受賞作から蒸留した10か条に沿って組んでいます。

1. **タイポグラフィ主導** — 本文は Noto Sans JP、見出しは Inter。装飾より文字のサイズと太さで階層を作る。
2. **読みやすい本文** — 行幅は約40字、行間は1.85。
3. **余白の規律** — 余白は8px倍数。記事は本文と右目次の2カラム。
4. **情報階層** — 1ページに見出し1はひとつ。日付と読了時間は見出しの直下に置く。
5. **短いモーション** — 300ms以内。動かすのは transform と opacity だけ。`prefers-reduced-motion` では止める。
6. **抑制された色** — アクセントは1色。本文コントラストは7:1以上。
7. **ダークモード** — システムの設定に従い、手動切替は保存する。
8. **目次と回遊** — 広い画面では目次を固定。狭い画面では折りたたむ。号の末尾に前日・翌日と関連3件。
9. **アクセシビリティ** — ランドマーク、可視フォーカス、44px以上の操作対象、スキップリンク。
10. **速さ** — 静的HTML。シンタックスハイライトはビルド時。JavaScriptは小さく保つ。

## 開発

```bash
npm install
npm run dev
```

本番と同じベースパス `/it-jissen-report/` で起動します。

```bash
npm run build
npm run preview
```

## 公開

`.github/workflows/pages.yml` が `main` への push で Pages にデプロイします。リポジトリの Pages ソースは GitHub Actions です。初回に有効化できない場合は、Settings → Pages → Build and deployment → Source を GitHub Actions にしてください。
